# 🚫 КАК ЗАБЛОКИРОВАТЬ ПОЛЬЗОВАТЕЛЯ

## 🎯 Быстрая инструкция (30 секунд)

```
1. Откройте бота
2. /admin
3. 👥 Управление пользователями
4. 🔍 Найти пользователя
5. Введите @username
6. Нажмите: 🚫 Заблокировать доступ
7. ✅ Готово! Пользователь заблокирован
```

---

## 📋 Что происходит при блокировке

### Для пользователя:
- ❌ **Теряет доступ к боту мгновенно**
- ❄️ **Токены замораживаются**
- 🚫 **Не может использовать репетитора**
- 📬 **Получает уведомление о блокировке**

### В базе данных:
- `access_code.is_blocked = True`
- `user.tokens_frozen = True`
- Подписка помечена как заблокированная

## 🔓 Как разблокировать пользователя

**Способ 1: Выдать новый доступ (рекомендуется)**
```
/admin → 👥 Управление → ➕ Добавить пользователя
→ Введите @username → Введите дни → ✅
```

Это:
- Создаст новый код доступа
- Разморозит токены
- Пользователь сможет работать

**Способ 2: Через базу данных**
```sql
-- Найти заблокированный код
SELECT * FROM access_codes WHERE activated_by = user_id AND is_blocked = 1;

-- Разблокировать
UPDATE access_codes SET is_blocked = 0 WHERE id = код_id;

-- Разморозить токены
UPDATE users SET tokens_frozen = 0 WHERE id = user_id;
```

## ❓ Частые вопросы

### Q: Можно ли заблокировать администратора?

**A:** Технически да, но НЕ рекомендуется.
- Администраторы имеют полный доступ через `ADMIN_IDS` в `.env`
- Блокировка кода не влияет на админские права
- Админ всё равно сможет пользоваться админ-панелью

---

### Q: Что если у пользователя нет активного доступа?

**A:** Кнопка блокировки покажет:
```
⚠️ У пользователя нет активного доступа
```

Блокировать нечего - доступ уже истёк.

---

### Q: Можно ли заблокировать отложенный доступ?

**A:** Да! Если выдали отложенный доступ:

**Вариант 1:** Подождать пока пользователь запустит /start, потом заблокировать

**Вариант 2:** Удалить через БД:
```bash
sqlite3 math_tutor.db
DELETE FROM access_codes WHERE code LIKE 'PENDING_username_%';
```

---

### Q: Блокировка обратима?

**A:** Да! Просто выдайте новый доступ через "➕ Добавить пользователя"

## ⚠️ Важные замечания

### Когда блокировать:
- ✅ Нарушение правил использования
- ✅ Злоупотребление токенами
- ✅ Окончание тестового периода
- ✅ Запрос самого пользователя
- ✅ Неуплата за продление

### Когда НЕ блокировать:
- ❌ Просто истёк срок подписки (истечёт автоматически)
- ❌ Пользователь задаёт много вопросов (это нормально!)
- ❌ Технические проблемы бота (не вина пользователя)

## 🔧 Техническая информация

### Что происходит в коде:

```python
# 1. Блокируем код доступа
active_code.is_blocked = True
active_code.block()  # Метод из модели

# 2. Замораживаем токены
await TokenService.freeze_tokens(session, user)

# 3. Сохраняем изменения
await session.commit()

# 4. Уведомляем пользователя (если возможно)
await bot.send_message(telegram_id, "🚫 Ваш доступ заблокирован...")
```

### Проверка блокировки в middleware:

```python
# В access_middleware.py
has_access, reason = await AccessService.check_user_access(session, user_id)

if not has_access:
    if reason == "blocked":
        await event.answer("🚫 Доступ заблокирован")
    # ...
```
